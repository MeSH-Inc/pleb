RFC-91: Ledger Transfers Protocol

1. Transfer Submission #

Clients submit settlement entries via POST /v1/transfers with an Idempotency-Key header containing a 128-bit UUIDv4 token. Retries after network timeouts reuse the identical key.

8. Clock Skew and Idempotency-Key Expiry #

Servers retain each Idempotency-Key record for exactly 86400 seconds (24 hours) measured from first commit timestamp. Reusing an active key returns the cached response when request bytes match, or returns HTTP 409 Conflict when the payload SHA-256 differs from the original request. Keys replayed after 86400 seconds are treated as fresh transfers.
